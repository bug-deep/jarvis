# Архитектура 0.1.0

## Компоненты

| Компонент | Файл | Ответственность |
|---|---|---|
| Облако | `src/cloud/server.js` | API активации, ключей, баланса, статистики |
| Шлюз | `src/cloud/gateway.js` | прокси DeepSeek, стриминг, учёт и списание |
| Бот | `src/cloud/bot.js` | код активации, бонус за канал, баланс |
| Хранилище | `src/cloud/store.js` | SQLite, идемпотентные операции |
| Локальный агент | `src/app/agent.js` | цикл tool-calling, подтверждения |
| Инструменты | `src/app/tools.js` | файлы, команды, ссылки, песочница |
| UI приложения | `src/app/ui/` | чат, активация, статистика, настройки |
| Админка | `src/cloud/ui/` | статистика, пользователи, начисление баланса |
| Оболочка | `src/electron/main.js` | окно Electron, запуск локального сервера, внешние ссылки |

## Поток активации

1. `POST /v1/device/code` — облако создаёт `user_code` (8 символов) и
   `device_code` (32 байта). В базе лежит только хеш `device_code`.
2. Пользователь отправляет `user_code` боту. Бот проверяет, что код не истёк,
   создаёт устройство и ключ, кладёт ключ в `device_codes.api_key_plain`.
3. Приложение опрашивает `GET /v1/device/token?device_code=…`, получает ключ
   **один раз** (поле очищается) и сохраняет локально.
4. Повторный опрос возвращает 202 — ключ уже забран.

Код живёт 10 минут. Ключ в чат бота не отправляется: он попадает сразу в
приложение, в боте — только подтверждение.

## Поток запроса

```
UI → локальный сервер → Agent
      Agent → облако /v1/chat/completions (stream, tools)
                облако → DeepSeek (stream, include_usage)
      Agent ← дельты текста и tool_calls
      Agent → инструмент (подтверждение в UI) → результат
      Agent → облако снова (tool result)
      облако: по usage считает стоимость и списывает баланс
```

Стоимость фиксируется в `usage` в момент запроса: смена прайса не переписывает
историю. Резерв не делается — проверяется минимальный баланс, списание идёт по
факту. При нуле — 402, запрос не уходит в DeepSeek.

## Данные

| Таблица | Поля (главные) |
|---|---|
| `users` | `tg_id`, `balance_micro`, `bonus_granted_at` |
| `devices` | `user_id`, `name`, `os` |
| `api_keys` | `hash`, `prefix`, `device_id`, `revoked_at` |
| `device_codes` | `device_code_hash`, `user_code`, `status`, `api_key_plain` |
| `ledger` | `delta_micro`, `kind`, `ref`, уникальный `(kind, ref)` |
| `usage` | `request_id`, токены, `cost_micro` |

Деньги — целые микро-рубли (1 ₽ = 1 000 000), чтобы не ловить ошибки float.
Баланс — материализованное поле, любое изменение пишется в `ledger`.

## Цены

Пиковый тариф DeepSeek, доллары за 1 млн токенов:

| Модель | Вход (cache miss) | Вход (hit) | Выход |
|---|---:|---:|---:|
| `deepseek-flash` | 0,30 | 0,006 | 1,20 |
| `deepseek-v4-pro` | 1,32 | 0,044 | 3,96 |

Стоимость = токены × цена / 1e6 × курс × наценка. Курс и наценка — в конфиге.
Off-peak вдвое дешевле, поэтому пиковый тариф даёт запас маржи.

## Решения

- **Ключ DeepSeek только на сервере.** Клиент не знает его и не может обойти
  баланс.
- **Инструменты выполняются на клиенте.** Шлюз не может командовать ПК: он
  только проксирует модель, решение о выполнении принимает локальный агент.
- **Подтверждение опасных действий.** Запись, удаление, команды — через
  модальное окно; по умолчанию отказ.
- **Песочница путей.** В режиме «Моя папка» проверяется `realpath` и родитель
  для ещё не созданных файлов; симлинки наружу блокируются.
- **История только локально.** На сервере нет текстов сообщений — меньше риска
  по 152-ФЗ и дешевле хранение.

## Проверка бота

`tests/bot.test.js` поднимает HTTP-сервер, изображающий Telegram Bot API, и
прогоняет реальные обработчики grammY: `/start` (регистрация), сообщение с
кодом (выдача ключа) и callback `bonus` (проверка подписки и начисление).
Токен и сеть Telegram для этого не нужны.

## Эксплуатация

Десктоп: Electron поднимает локальный сервер на свободном порту и открывает
окно. Адрес облака хранится в настройках приложения (на чужом ПК его задают
при активации). Установщик Windows собирается electron-builder на Windows/CI.

Сервисы — три systemd-юнита: `jarvis-cloud` (8098, LAN), `jarvis-app`
(127.0.0.1:8096), `jarvis-app-tunnel` (проброс 8096 на ПК). Шаблоны юнитов
лежат в `config/*.service` с подстановкой `__ROOT__`. На ПК — ярлык «Jarvis Dev»
из реестра `service-launcher`.

Админка на `/admin/` авторизуется заголовком `x-admin-token`; токен живёт
в `secrets/jarvis-desktop.env` и вводится в браузере один раз. Через неё же
можно активировать устройство без бота: список ожидающих кодов → «Активировать»
(пользователь берётся из `ADMIN_TG_ID`).

Портативная сборка Windows читает `jarvis.json` рядом с `.exe` — там можно
задать `cloudUrl`, чтобы не вводить адрес руками.

## Ограничения и следующий шаг

- Установщик NSIS: есть портативная сборка, installer собирается на Windows/CI.
- Подпись кода и DPAPI для ключа на Windows — следующие шаги.
- Оплата: СБП через эквайринг, вебхук, идемпотентное начисление.
- Голос: серверный ASR + edge-tts, либо DeepSeek TTS (дорого).
- Postgres и несколько инстансов, если пользователей станет больше сотен.
